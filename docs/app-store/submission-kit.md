## 2. App 描述

> 写作原则：不写「革命性」「颠覆」这类词；不承诺没做到的功能；
> 描述里出现的每一项都必须在当前构建里真实可用。

```
炉灵是给几个朋友常驻的语音空间。

点一下就进去，不用打招呼，不用约时间。
里面有人就说话，没人就挂着——像是有人在隔壁房间，
你知道他在，但不必一直说话。

· 一键进出。主屏幕点一下进圈，再点一下离开。
· 看得见谁在。进圈前就知道里面有没有人、有几个。
· 没人时留句话。长按录一条 15 秒以内的语音便签，
  下一个进来的人会看到红点，听完自动消失。
· 多个圈子。家人一个、朋友一个，各自独立，互不打扰。
· 需要敲门。开启后，陌生的加入者要先敲门，里面的人放行才进得来。
· 端到端加密（可选）。开启后连服务器也听不到内容。

关于隐私：
炉灵没有账号体系，不需要手机号或邮箱，不收集通讯录。
进圈靠圈子口令，没有陌生人匹配、没有附近的人、没有公开房间列表。
你也可以用自己的服务器——服务端代码是开源的。
```

**字数控制**：App Store 描述上限 4000 字符，上面约 400 字，够用。
首屏只显示前 3 行，所以前 3 行必须自己成立。

## 4. 年龄分级问卷

按当前功能，预期分级 **17+**（因含不受限的用户间通讯）。

| 问题 | 答案 | 依据 |
|---|---|---|
| 暴力/恐怖/色情等内容 | 全部「无」 | App 本身不提供任何内容 |
| 是否含用户生成内容 | **是** | 语音、文字、图片消息 |
| 是否含不受限的网络访问 | 否 | 无内置浏览器 |
| 是否含用户间交流功能 | **是** | 这是核心功能 |

⚠️ UGC 一旦选「是」，Apple 会要求四件套齐备（见第 7 节）。

## 5. 隐私标签（App Privacy）

依据 `app/ios/Runner/PrivacyInfo.xcprivacy`，两者必须一致，否则会被自动检查退回。

### 收集的数据

| 数据类型 | 关联到用户 | 用于追踪 | 用途 |
|---|---|---|---|
| Audio Data（语音便签） | 是 | 否 | App 功能 |
| Name（昵称） | 是 | 否 | App 功能 |
| Coarse Location（位置共享） | 是 | 否 | App 功能 |
| User ID（本机生成） | 是 | 否 | App 功能 |

### 不收集的（如被追问，理由如下）

- **实时通话音频**：经 SFU 实时转发，不落盘
- **文字与图片消息**：走 LiveKit data channel 直达成员，不经过信令服务器
- **通讯录、相册**：从不访问（图片经文档选择器，不读相册）
- **IDFA**：未集成 AppTrackingTransparency，无任何广告/分析 SDK

## 6. 出口合规

| 问题 | 答案 |
|---|---|
| 是否使用加密 | 是 |
| 是否仅用 Apple 系统加密 | **否**（带了 libwebrtc、hashlib） |
| 算法是否自研/专有 | **否**，均为标准算法 |
| 分类 | 5D992.c，ENC 740.17(b)(1) |

`Info.plist` 里**刻意不写** `ITSAppUsesNonExemptEncryption`。

填 `true` 会被 altool 预检以 ITMS-90592 拒绝（它会继续索要
只发给 CCATS 持有者的 `ITSEncryptionExportComplianceCode`）；
填 `false` 又与事实不符。不写，改在 ASC 网页上按上表逐题回答 ——
这才是自分类该走的路径。

⚠️ 每上传一个新构建，TestFlight 页面都会要求回答一次这组问题。

⏰ **上架后义务**：次年 2 月 1 日前提交年度自分类报告。
详见 `docs/compliance/encryption-export.md`。

## 7. 审核备注（App Review Information）

> 这是**风险最高**的一栏。审核员进不去 App 就会直接按 2.1 拒。

```
【如何进入 App】

炉灵是私密小圈子语音工具，需要圈子口令才能进入。
请使用以下演示凭据：

  服务器：wss://lares.westus.cloudapp.azure.com:443/ws
  （此为默认服务器，App 首次启动即已填好，无需手动输入）

  圈子 ID：review
  圈子口令：amber-cedar-lumen-quiet

步骤：
1. 首次启动会先显示《内容规范》，需点击同意才能继续
   （这是 UGC 必需的用户协议，不同意无法进入主界面）
2. 在主屏幕点击「加个圈子」→「粘贴邀请链接」
3. 粘贴：lares://circle/review?name=Review
   （也可以直接输入圈子 ID：review）
4. 点击新出现的「Review」圈子卡片
5. 提示输入口令时，填入：amber-cedar-lumen-quiet
6. 进入后即可看到成员列表并使用麦克风

注：主屏幕默认显示的「我们的圈」是示例圈子，
未配置口令，请使用上面的 review 圈子进行测试。

如需看到多人在线的效果，请提前邮件告知
support@laresapp.org，我们会安排一位成员同时在线配合测试。

【关于 Guideline 1.2 —— 本 App 不是陌生人社交】

炉灵不含任何陌生人发现机制。代码层面可验证：
· 无用户匹配、无「附近的人」、无公开房间列表、无推荐算法
· 唯一的加入方式是知道圈子 ID 并持有该圈口令
· 圈子由用户自行创建，口令由创建者线下告知朋友
· 服务端不维护任何公开可检索的圈子目录

【UGC 四件套位置】

1. 举报：成员头像轻点或长按 → 举报；消息长按 → 举报
   共 7 类理由，提交后生成邮件发往 support@laresapp.org
2. 屏蔽：举报流程内直接提供，也可在成员菜单单独屏蔽
   屏蔽后立即静音并隐藏其消息，无需等待处理
3. 用户协议：首次启动展示《内容规范》，须同意方可进入
   （`ContentPolicyGate`，同意状态按版本号记录，条款实质变更会重新征求同意）
4. 处理承诺：24 小时内，已写入支持页面

【端到端加密说明】

部分圈子可开启 E2EE。开启后服务器无法解密内容。
这是可选功能，默认关闭。审核用的演示圈子未开启加密，
以便审核员正常体验全部功能。
```

⚠️ **提交前必须**：
1. 在服务器上建一个**专用审核圈子**，配独立口令（不要给 `fengming`）
2. 把口令填进上面的占位符
3. 自己用一台干净设备按上述步骤走一遍，确认能进
